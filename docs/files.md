# Files

- `skills/notion-ai-relay/` is the folder `npx skills add` installs: `SKILL.md`, `references/`, `agents/openai.yaml` and a copy of `LICENSE`. The rest of the repository is not installed. Releases up to 0.1.0, and the commits before the move, kept the Skill at the repository root, so installing one of them copies the whole repository.
- [SKILL.md](../skills/notion-ai-relay/SKILL.md) defines target selection, configuration retrieval, MCP execution, and result verification.
- [CHANGELOG.md](../CHANGELOG.md) records each release.
- [Discover](../skills/notion-ai-relay/references/discover.md) holds the rules for listing Custom Agents, and `SKILL.md` sends an Agent listing there. Its section on retrieval completeness is a test-checked copy of the execution procedure's. Rules for every read, such as rate limits, stay in the execution procedure.
- [Read Custom Agent settings](../skills/notion-ai-relay/references/read-configuration.md) covers finding an Agent, configuration versions, and resume state.
- [Read Notion Skills](../skills/notion-ai-relay/references/read-skills.md) covers listing and finding Notion Skills, instruction pages, and supporting resources.
- [Execute through MCP](../skills/notion-ai-relay/references/execute-via-mcp.md) covers tool mapping and execution checks.
- [Agent retrieval](agent-retrieval.md) compares ways to read Custom Agent instructions and settings and records test runs. It is reference material, not part of Relay's instructions.
- [Compatibility and evidence](compatibility.md) is the dated matrix of synthetic checks, historical live records, blockers, and unverified environments.
- [Installation maintenance](install-maintenance.md) covers finding the installed copy, updates, backups, rollback, and what to send for support.
- [Scheduled runs](scheduling.md) shows how to run an Agent's task from your own scheduler with no one present, and what such a run writes and holds.
- [Permissions and client settings](permissions.md) lists what Relay tells your assistant to do and which client settings stop which calls, as measured.
- [Security policy](../SECURITY.md) says what to report privately and where.
- [Structural checks](structural-checks.md) covers the CI check. `scripts/` holds the check and the command CI runs.
- [Troubleshooting](troubleshooting.md) lists what a stopped run usually needs from you. Relay does not load it.
- [Example dry run](dry-run-example.md) shows one unedited request, the tools called and the reply, from a synthetic local MCP.
- Decision cases without a scorer are in `evals/`, where CI checks that each case has a unique `id` and a non-empty expected outcome; `tests/` keeps the suites whose scorers and fixtures CI runs. Each folder has its own replay steps. Neither is runtime instructions.
- [Next-step cases](../evals/next-step/README.md) check what a stopped run's report tells the user to do, against a [local eval fixture](../tests/eval-fixture/mock_mcp.py) that also serves the [dry-run cases](../evals/dry-run/README.md).
- [Security-boundary execution cases](../tests/security/README.md) provide a synthetic MCP fixture, attempted-call scoring, and separate host-denial tests.
- [Write lifecycle execution cases](../tests/write-lifecycle/README.md) exercise synthetic writes, unknown outcomes, verification, stop, and resume through a fault-injecting MCP fixture.
- [Resume-handoff cases](../tests/resume-handoff/README.md) check resuming interrupted work and the handoff returned when work stops.
- [Response-language cases](../tests/response-language/README.md) check the language of replies and of content for destinations against supplied snapshots.
- [Client/permission/resource fixtures](../tests/compatibility/README.md) define the finite compatibility replay and pure-comparison boundary checks.
- [Installation maintenance replay](../tests/install-maintenance/README.md) is an opt-in, networked replay of installing and updating into temporary directories; CI does not run it.
- `.github/` holds the CI workflow, the issue form, and the Dependabot settings.
