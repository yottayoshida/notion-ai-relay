# Compatibility and evidence

Notion AI Relay distributes instructions, not an MCP server. Skill loading and available MCP capabilities depend on the client.

- **Against a real Notion workspace**, the recorded Relay runs are five, all in Claude Code on 2026-11-06 and one of them a control on an earlier version; none wrote, and four had the write tools removed ([recorded runs](agent-retrieval.md#recorded-runs), [historical live observations](#historical-live-observations--not-current-source-pass)). The maintainer's other live checks are recorded as hosted Notion MCP tool calls, not Relay runs: in Claude Code on 2026-11-05, and with no client recorded on 2026-11-19 and 2026-11-24 ([retrieval record](agent-retrieval.md), [connection capabilities](#connection-capabilities-what-the-evidence-does-and-does-not-establish)).
- **Not observed live**: any write, and any run in Codex or Pi. Every recorded write, and every recorded Codex and Pi run, used only this repository's local fixtures, on which Claude Code has run too ([finite fixture runs](#finite-fixture-runs) and the dated sections under it).

Choose a client and connection by the capabilities your task actually needs; an MCP connection alone does not establish Agent settings access, full resource retrieval, write verification, or authorization. **A synthetic PASS is not live Notion compatibility.**

## How to read the matrix

- **PASS / FAIL**: observed result for the named finite fixture and frozen runtime, not a guarantee for another workflow or revision.
- **blocked**: the intended client/environment could not execute the sample under the authorized conditions; the reason must remain visible.
- **unverified**: no applicable execution evidence.
- **historical record**: earlier live observation, with its original date/client/constraints; not rerun against current source.
- **Repeat runs**: scenarios run several times are in [Repeat runs](#repeat-runs-2026-11-26).

Fixture authorization is synthetic reads/calculation and dry run only, with no real credentials, production data, external mutations or persisted run-state changes. Client-specific private adapters and raw logs are not part of the distribution. The [replay protocol](../tests/compatibility/README.md) defines the public server, tools, cases, scoring and native-client minimum. Each case ID below is the `--case` argument to that protocol.

A failing session appears once under each scorer error it produced, so a row's error counts can add up to more than its failures. An error is counted up to its first variable part: `wrong final confirmed: […]` counts as `wrong final confirmed`. In `run-history-pages` both failures read your own chat's configuration event and the editable page, then held the sum without reading `input`, as in the earlier replays above. In `comparison-code` every session returned `[false, true, false, false, true, true]` against the expected `[false, true, false, false, false, true]`: the fifth vector's label arrived as `e` followed by a combining acute accent (U+0065 U+0301) and was sent to `calculate` as the single character `é` (U+00E9). Sessions took 12 to 38 seconds and cost US$0.03 to US$0.18 each; the fifteen cost about US$1.29 together, the pilot US$0.13.

Five sessions do not establish a rate. At 95% one-sided confidence (Clopper–Pearson), 0 failures in 5 still allows a failure rate of up to 45%, 1 failure up to 66%, 2 up to 81%, 3 up to 92% and 4 up to 99%.

Before these runs, a final message that was not readable as JSON made the write-lifecycle scorer skip its check of the persisted checkpoints along with the report, and neither scorer said which report it had not scored, so a format failure could hide a missing checkpoint and leave a wrong result uncounted. The write-lifecycle scorer now checks the persisted checkpoints either way and reports a final message that is JSON but not an object instead of stopping with an error, and both scorers name a report they could not read as `unscored`. Rescored with the changed scorer, the eight Claude Code write-lifecycle sessions of 2026-11-25 keep every verdict and error; the `no-readback` session's fenced report, which this scorer does not read, is now named as `unscored`.

## Choosing an environment

| Operation | Required information or capability |
|---|---|
| List Custom Agents | An MCP agent-listing capability. Results cover the scope exposed by the connection |
| List Notion Skills | An MCP Skill-listing capability, or a known Skill page or database. The hosted Notion MCP lists only Skills enabled for external MCP clients |
| Carry out a Custom Agent's task | Its instructions, a verified or user-supplied link to the target, required settings and input, and the necessary MCP operations |
| Carry out a Notion Skill's task | Its instruction page, required references and attachments, current input, and the necessary MCP operations |
| Run on a schedule | A separately configured scheduler or event receiver |

For discovery, require a real catalog capability or an explicitly known page or database listing Skills. For execution, require readable current adopted instructions, complete necessary resources, allowed tools and task authorization; do not infer these from discovery visibility or edit rights. For dry runs, retain read/coverage limitations and do not mutate messages, completion ledgers or local resume state.

If the native client/model or connection is blocked, resolve that specific prerequisite through the client's configuration/authentication interface and obtain any missing evaluation authorization. Do not substitute another model or a different client and label its result as the blocked cell's PASS. Credentials and business content do not belong in compatibility reports.
