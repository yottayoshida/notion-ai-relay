# Permissions and client settings

Client permission rules stop or allow a call per tool or command ([security policy](../SECURITY.md)), so they cannot express the finer rules below, such as `https` only, no redirects, the 1 MB limit or what a go-ahead list must contain. Nor can they tell `notion-query-sessions` filtered by the Agent's ID, which Relay uses, from the same tool searching run titles.

## What Relay tells your assistant

Relay uses the MCP tools and argument schemas your environment exposes, and needs no Computer Use, browser automation, particular operating system, or client-specific API. When Notion MCP returns a download URL for a file in the same run, Relay downloads it over `https` from a host name, never `localhost` or an IP address, instead of asking you to paste it, in a client that can save it outside your project and Relay's folder, and extract an archive there: from a tar archive of at most 100 members it takes regular files up to 1 MB, and it reports a redirect, other archives (Office files included) and anything beyond these limits. No other URL is downloaded outside MCP, except by a script you approve. Apart from reading its own files and handling these downloads, before the first write, message, non-Notion connection, local file or command you did not name, Relay lists them, with what each write would contain, from what, and any recorded run's date, and waits for your go-ahead. Code from the instructions, their files or the data runs on this machine only if you ask for that script and approve the command you are shown, and then with your access, network included; otherwise its calculation is reproduced by reading it, or reported when it cannot be.

## Claude Code settings

The deny rules in the [README](../README.md#limits) name the session tools that the [execution boundaries](../skills/notion-ai-relay/SKILL.md#execution-boundaries) tell your assistant never to call. A tool's full name starts with `mcp__<server>__`, where `<server>` is the name the connection has in your client, such as `notion` for a server you added under that name or `claude_ai_Notion` for the claude.ai connector; `/mcp` lists the servers, and the rules use `mcp__*__` to cover any name. The tool names are the hosted Notion MCP's; a connection that spells them differently needs its own spelling. `notion-search-sessions` is denied too: the execution boundaries forbid searching past sessions by topic. Put them in the project's `.claude/settings.json`: in your user settings they would also stop those tools outside Relay. `/permissions` shows whether they are loaded.

How these rules behaved in each permission mode is recorded in [client permission rules](compatibility.md#client-permission-rules-2026-11-25). In short, they stopped the session tools in the default, `dontAsk`, `acceptEdits` and `auto` modes, `ask` rules refuse in `claude -p` because no one can answer, and bypass mode was not tested. So with every tool approved automatically, the deny rules stop only the session tools: writes, messages and commands go through unless you approve them one at a time. With commands approved one at a time, one download asks several times.

## Dry runs

For a dry run, deny the write tools, as the [recorded runs](agent-retrieval.md#recorded-runs) did: in Claude Code a deny rule takes precedence over an allow rule, though here only a settings deny against a command-line allow was measured. Allowing only read tools is not enough on its own, because `dontAsk` refuses only what no allow rule covers, and allow rules in your user or project settings count too (not measured here). For example, `claude -p "<request>" --permission-mode dontAsk --allowedTools Skill Read mcp__notion__notion-search mcp__notion__notion-fetch mcp__notion__notion-search-agents mcp__notion__notion-get-self mcp__notion__notion-get-tool-access mcp__notion__notion-query-sessions mcp__notion__notion-list-session-events mcp__notion__notion-read-session-event mcp__notion__notion-get-enabled-skills mcp__notion__notion-download-skill mcp__notion__notion-get-file-download-urls mcp__notion__notion-query-data-sources --disallowedTools mcp__notion__notion-create-pages mcp__notion__notion-update-page`, with your server name in place of `notion`, the read tools the target needs, and every write tool your connection lists after `--disallowedTools`. In the [recorded check](compatibility.md#client-permission-rules-2026-11-25), with no other settings loaded, a write left out of the allow list was refused. Fixture replays have shown sessions calling a write tool during a dry run ([finite fixture runs](compatibility.md#finite-fixture-runs)). `dontAsk` also refuses shell commands that chain after `cd` or use parentheses ([download URLs](compatibility.md#download-urls-2026-11-19)) and commands that write through a redirection ([download URLs and archives](compatibility.md#download-urls-and-archives-2026-11-24)), so a download step can stop in a dry run.

## Writes and the Agent's own schedule

Notion's [help](https://www.notion.com/help/notion-mcp), read 2026-11-25, says "MCP tools act with your full Notion permissions"; it does not say whether an edit shows your name. A connection a team shares acts as the shared account. If you pause the Agent's schedule in Notion, its recorded settings age ([what the run-history route assumes](agent-retrieval.md#what-the-run-history-route-assumes)).
