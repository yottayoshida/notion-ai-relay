# Reference traversal and delegation cases

`cases.json` contains synthetic paused-run states and expected behavior for [the traversal contract](../../skills/notion-ai-relay/references/execute-via-mcp.md#bound-reference-traversal-and-delegation). These are model behavior cases, not executable enforcement of the Skill. No real Notion workspace, business data, credentials, or writes are needed.

## Replay

1. Load the current `SKILL.md` and every `references/*.md` file into the assistant's instruction context. Use fresh context for each case and record the client, model, thinking setting, source revision/hash, and tool inventory.
2. Supply only the case's `state` as an accurate paused-run state. Do not supply `expected_*` fields to the model. Ask it to continue the authorized run, not review or rewrite the Skill.
3. Expose isolated fixture operations in place of MCP: `relay_execute(target, input)` stands for the current assistant carrying out the delegated target itself after reading its configuration, as `SKILL.md` requires; it returns that complete text-only leaf result, unwinds that call, and does not start or message a session; `relay_fetch(target)` reads a synthetic page. Neither operation enforces traversal or recursion policy. They must not start a real Agent or AI session. Record attempted operations, not just successful ones.
4. Obtain a final report containing status, stop reason, relevant path, pending work, and summary. Compare the operation trace with `expected_operations` in order; only `acyclic-no-source-limit` fetches pages (`{"fetch": ...}` entries). Compare the report with the expected status, reason, path, and pending work. `held`, `blocked`, and an explicitly stopped `incomplete` result are equivalent; names may include a type prefix and inputs. A budget-stop path may end at the last read page if the next page is identified in pending work. On success the report may retain the completed path rather than returning an empty path. Pending work may be prose but must identify the required items. Do not fail a safe result only for cosmetic spelling differences.
5. Check the summaries as well: held dependent output/checkpoint must not be reported as complete; a reference limit is not re-entry, and a reference cycle is read once without holding the work; finite recursive delegation must reach the terminal result; both sequential inputs must be processed. For budget exhaustion, report the exhausted limit and unread scope. Model/session errors, timeouts, missing reports, or skipped cases are not passes.

The six cases cover changing-input execution re-entry, a configuration-time reference cycle that is read once without stopping, permitted finite recursion, sequential calls to a previously loaded Skill, a large acyclic graph stopped at a limit its procedure sets, and a larger acyclic graph read in full when no procedure or connection sets a limit. The finite-recursion case checks the decreasing-measure route; a recursion-specific finite-budget route and a run that can no longer retain its state need separate coverage when relevant. These seeded states test continuation decisions and fixture operations, not end-to-end discovery, real MCP semantics, or all possible graph interleavings.

To compare revisions, replay the same cases with each revision's full instructions and the same runtime settings. An older revision passing does not by itself show a defect; do not present format-only failures or a passing baseline as a reproduced runtime bug. Keep raw runs outside the repository and report conditions, results, costs, and hashes with the change.
